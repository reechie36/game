# Letter Rise - Local Launch & Deployment Guide

This guide covers how to launch the **Letter Rise** Web Edition locally for development and how to deploy it to **Vercel** (or other static hosting platforms).

---

## 1. Launching Locally

The web game is built with vanilla ES modules, Canvas 2D, and Web Audio. Because it uses ES modules and fetches local JSON/audio assets, it must be served over HTTP (not directly via `file://`).

### Option A: Using Node.js (Recommended)

Run the included zero-dependency dev server from the repository root:

```bash
npm run dev
```

Open your browser to:
**[http://localhost:8080](http://localhost:8080)**

To run on a custom port:
```bash
PORT=3000 npm run dev
```

The server serves the root `index.html`, the browser application from `web/`,
and shared runtime files from `assets/`. To run it without npm:

```bash
node web/tools/dev_server.mjs
```

### Option B: Using Python

If you already have Python installed:

```bash
python3 -m http.server 8080 --directory .
```

Then visit **[http://localhost:8080](http://localhost:8080)**.

### Option C: VS Code Live Server Extension

1. Install the **Live Server** extension in VS Code.
2. Right-click the root `index.html` and click **Open with Live Server**.

Live Server must use the repository root as its workspace directory. The root
page and `/assets/**` paths are part of the deployment layout.

### Python edition

The original pygame edition is maintained separately under `python/` and is
not part of the static web deployment:

```bash
python3 -m pip install -r python/requirements.txt
python3 python/main.py
```

## 2. Deploying on Vercel

Vercel provides instant static hosting with worldwide edge CDN, automatic HTTPS, and asset caching.

The repository includes a ready-to-go [`vercel.json`](vercel.json):
- Automatically runs `node web/tools/generate_env.mjs` during build.
- Serves static files directly from the root.
- Caches shared fonts, audio, and vocabulary data at `/assets/**` with 1-year immutable cache headers.

### Method 1: Via Vercel Web Dashboard (Simplest)

1. **Push your code to GitHub / GitLab / Bitbucket**:
   ```bash
   git add .
   git commit -m "Add Letter Rise Web port and Vercel config"
   git push origin main
   ```

2. **Import into Vercel**:
   - Go to [vercel.com/new](https://vercel.com/new) and log in.
   - Select your Git repository and click **Import**.

3. **Configure Project Settings**:
   - **Framework Preset**: Select **Other**.
   - **Root Directory**: `./` (leave default).
   - **Build Command**: `node web/tools/generate_env.mjs` (detected from `vercel.json`).
   - **Output Directory**: `.` (detected from `vercel.json`).

4. **Add Environment Variables (for Supabase Leaderboard)**:
   In the **Environment Variables** section, add:
   - `SUPABASE_URL` = `https://your-project.supabase.co`
   - `SUPABASE_ANON_KEY` = `your-public-anon-key`

   *(If you don't configure Supabase, the game works normally in offline mode and saves personal bests to local storage).*

5. **Deploy**:
   - Click **Deploy**.
   - Your game is live in seconds at `https://your-project.vercel.app`!

---

### Method 2: Via Vercel CLI

1. Install Vercel CLI:
   ```bash
   npm install -g vercel
   ```

2. Log in and link:
   ```bash
   vercel login
   vercel link
   ```

3. (Optional) Set Supabase environment variables:
   ```bash
   vercel env add SUPABASE_URL production
   vercel env add SUPABASE_ANON_KEY production
   ```

4. Deploy to production:
   ```bash
   vercel --prod
   ```

### Verify a deployment

After deployment, check the root page and representative shared assets:

```bash
curl -I https://your-project.vercel.app/
curl -I https://your-project.vercel.app/assets/fonts/FiraMono-Regular.ttf
curl -I https://your-project.vercel.app/assets/sounds/chips_place_1.wav
```

The requests should return `200`. If the page loads without fonts or audio,
confirm that the project root is `./` and that `/assets/` was not configured as
a separate output directory.

## 3. Supabase Leaderboard Configuration (Optional)

If you wish to enable the global leaderboard:

1. Create a project at [supabase.com](https://supabase.com).
2. Run this SQL in the **SQL Editor** to create the table and query RPC:

```sql
-- 1. Create Leaderboard Table
create table public.leaderboard (
  id bigint generated by default as identity primary key,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  player_name text not null,
  score numeric(10,2) not null,
  rarest_word_found text default '-'::text,
   client_id text not null,
   mode text not null default 'endless' check (mode in ('endless', 'time_attack'))
);

-- 2. Enable Row Level Security (RLS)
alter table public.leaderboard enable row level security;

-- Allow anonymous inserts
create policy "Allow anonymous insert"
  on public.leaderboard for insert
  with check (true);

-- 3. Create Leaderboard RPC Function
create or replace function public.get_leaderboard(
  requested_client_id text,
   result_limit integer default 100,
   requested_mode text default 'endless'
)
returns json
language sql
security definer
as $$
  with ranked as (
    select
      row_number() over (order by score desc, created_at asc) as rank,
      player_name,
      score,
      rarest_word_found,
      client_id,
      (client_id = requested_client_id) as is_me
   from public.leaderboard
   where coalesce(mode, 'endless') = requested_mode
  )
  select coalesce(json_agg(r), '[]'::json)
  from (
    select * from ranked
    limit result_limit
  ) r;
$$;
```

For an existing leaderboard, run this migration before deploying the updated
client. Existing rows are assigned to Endless, preserving the old board:

```sql
alter table public.leaderboard
   add column if not exists mode text default 'endless';

update public.leaderboard
set mode = 'endless'
where mode is null;

alter table public.leaderboard
   alter column mode set default 'endless',
   alter column mode set not null;

alter table public.leaderboard
   drop constraint if exists leaderboard_mode_check;

alter table public.leaderboard
   add constraint leaderboard_mode_check
   check (mode in ('endless', 'time_attack'));

drop function if exists public.get_leaderboard(text, integer);
```

After the migration, rerun the `create or replace function` statement above so
the RPC includes its new `requested_mode` parameter and filters by mode.

## 4. Deploying to Other Static Hosts

### Cloudflare Pages
- **Build command**: `node web/tools/generate_env.mjs`
- **Build output directory**: `.`
- **Environment variables**: Add `SUPABASE_URL` and `SUPABASE_ANON_KEY` in **Settings > Environment Variables**.

### Netlify
- **Build command**: `node web/tools/generate_env.mjs`
- **Publish directory**: `.`
- Add environment variables in **Site configuration > Environment variables**.

### GitHub Pages
- Go to repository **Settings > Pages**.
- Source: **Deploy from a branch** -> branch: `main`, folder: `/ (root)`.
